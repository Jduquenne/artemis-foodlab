# Development

Everything needed to install, run, verify and deploy the front end. "Verified" = command executed during the 2026-10-07 migration.

## Prerequisites

- Node.js **24 or later** (`package.json` `engines.node: ">=24"`, CI uses Node 24).
- The backend repo `meals-planning-api` lives next to this one (`../meals-planning-api`, sibling folder, not a subfolder). It is worked on by a separate Claude Code session — see `docs/api.md` § Working with the API session.

## Install

```bash
npm install
```

## Environment variables

| Name | Where | Notes |
|---|---|---|
| `VITE_API_URL` | `.env` (local, gitignored) and `.env.production` (committed) | API base URL, bare: no trailing slash, no `/api`. `apiClient` concatenates `${API_URL}${path}`. Not a secret (it ends up in the bundle). Without `.env`, no request succeeds in dev. |

- **Agents never edit `.env*` files** — the owner manages them (see `AGENTS.md`). To test against a local API, call it with `curl` instead of repointing the front.
- No GitHub secret is needed for the build.
- Planned (not live): `VITE_GOOGLE_CLIENT_ID` for Google sign-in (`docs/api.md` § Planned).

### Golden-rule checks (grep)

Run from the repo root (bash/Git Bash; in PowerShell use `Select-String` or Claude Code's Grep tool with the same patterns). Each command should print nothing:

```bash
grep -rnE "as unknown as|eslint-disable|: any\b|<any>" src
grep -rnE "dark:(text|bg)-slate-|bg-slate-900/" src
grep -rn "/artemis-foodlab/" src
grep -rn "core/services" src/core/logic
```

Comments (rule "zero comments", except `src/vite-env.d.ts`) are not reliably greppable; review the diff.

Known pre-existing hits:

- Second command: 217 `dark:bg-slate-*` / `dark:text-slate-*` occurrences in 97 files (dashboard, freezer, journal, planning, recipes, builder, shopping, shared UI), counted on 2026-10-07. The theming rule stands: they are fixed progressively, feature by feature, during the P4 refactoring or the P5 tablet pass (`docs/roadmap.md`). Until then, a task must introduce **no new occurrence**, and a file being reworked should be cleaned.
- Third command: `src/shared/components/ui/legalContent.ts` — the public app address in the legal notice. Permanent exception.

## Branches and deployment

- **`master` = production**, **`Dev` = working branch**. A push on `master` triggers `.github/workflows/deploy.yml`: `npm ci` → `npm run lint` → `npm run build` → GitHub Pages (`https://jduquenne.github.io/artemis-foodlab/`). The build reads `VITE_API_URL` from `.env.production`.
- In production on the API since 2026-09-09. Rollback marker tag `prod-pre-api`; prefer rolling forward over reverting.
- **Deploy the API before the front** whenever the front depends on a new endpoint or field (e.g. profiles, demo mode). Never merge to `master` a change that depends on an endpoint not yet deployed on Render — confirm it is live first.
- Lesson (2026-09-08): API code deployed before its Prisma migration ran → 500 `ColumnNotFound` in prod. API-side concern, but check the endpoint actually responds before shipping the front.
- API hosting: Render free tier (build runs `prisma migrate deploy`, health `/health`), database and storage on Supabase. Infra details live in the API repo.

## Versioning

`package.json` `version` is the single source of truth, mirrored in `public/version.json` (also regenerated by `vite.config.ts` at build). Bump on every commit — rules in `docs/conventions.md` § Versioning. `package-lock.json` lags one version behind after each bump (known, accepted).

## Debugging

- **Render cold start** (free tier): the first request after ~15 min of inactivity can take 30-60 s. `useDelayedFlag` shows "Réveil du serveur…" after 5 s (splash + login). No `fetch` timeout on purpose.
- **Token / config "not fixed" reports**: first ask whether it happens **locally or in prod** (URL in the Network tab), then decode `exp − iat` of the `POST /auth/login` token. The local API reads its own gitignored `.env`, not Render's settings. Prod access-token TTL is 30 days.
- **Unexplained prod logouts** (open, see `docs/roadmap.md`): copy the `refreshToken` from the failing refresh payload, then on the API database: `SELECT … FROM refresh_tokens WHERE token_hash = encode(sha256('TOKEN'::bytea),'hex')`.
- **Slow app / white screen during tests**: check that no Chrome DevTools network throttling ("Slow 4G") is left on before investigating further.

## Known issues

- **Case-insensitive disk**: the repo disk is case-insensitive and git runs with `core.ignorecase=true`. A rename that only changes case must go through `git rm --cached` + `git add`, otherwise the Linux CI does not find the file (owner action).
- **Line endings**: `.gitattributes` (`* text=auto eol=lf`) + `git config core.autocrlf input` fixed fake "89 modified files" CRLF noise.
- **Parallel agents on the same checkout** can produce transient lint errors (a file captured mid-edit). Re-run the lint before concluding.
- `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24` in the workflow is a workaround to remove when the actions allow it.
- `.claude/settings.local.json` is listed in `.gitignore` but still tracked — owner to run `git rm --cached .claude/settings.local.json`.

### WSL (legacy)

Sessions moved from WSL to PowerShell on 2026-10-07. Kept for reference:

- `npx tsc --noEmit` on WSL once gave a false clean result (filesystem cache); a removed export still imported elsewhere broke the CI build. Always grep consumers before removing an export.
- `pkill -f vite` returned exit 144 and killed the shell; avoid starting `npm run dev` in the background without need.
